# Locations

- Skills source: `~/code/personal/agent-skills`, or `~/Documents/personal/agent-skills` on machines that keep repos there. Installed copies live in `~/.gitgud/skills`, linked into `~/.claude/skills` and `~/.pi/agent/skills`. After pushing, run `gitgud update --global` and `gitgud apply --global` from outside the repo; inside it, gitgud reads the working tree and can fail on stale frontmatter.
- Skill map of every skill, playbook and principle link: `node tools/skill-map/build.mjs` in that repo.
- Session logs: Claude Code, including T3 Code threads, in `~/.claude/projects/*/*.jsonl`; Pi in `~/.pi/agent/sessions/`.
- Pi models and defaults: `~/.pi/agent/settings.json`.
- Pi powerball extension (the toggle that puts yesh-router in the system prompt, plus the todo tool and the worker contract for child agents): its own repo, `github.com/Yeshwanthyk/pi-powerball`, checked out at `~/code/personal/pi-powerball`. Install with `pi install git:github.com/Yeshwanthyk/pi-powerball`, or for local development list the checkout path under `packages` in `~/.pi/agent/settings.json`. Claude Code gets the same mode from `config/agents/powerball-worker.md` and `config/statusline/`.
- Worktree seeding: `~/.local/bin/cowt` symlinks to the installed `~/.gitgud/skills/yesh-router/bin/cowt` (source: `skills/yesh-router/bin/cowt`), so it updates with `gitgud apply`, never from a working checkout. `cowt init <repo>` adds a marked block to that repo's own `post-checkout` (`.git/hooks`, or `.husky/` / `.vite-hooks/` beside their `_` runner), so every `git worktree add` from any tool gets copy-on-write `node_modules`. Set up in ky, oblong, scotty, ziggy. Undo per repo with `cowt uninit <repo>`; no global git config is involved.
