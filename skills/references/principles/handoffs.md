# Handoffs

**Read when:** work resumes after a restart, an agent is replaced, or a new receiver lacks the working context.

- Preserve a short checkpoint with the objective, scope, material decisions, completed work and evidence, outstanding work, and next action. Reuse an existing record when it supplies this context. Include the artifacts or locations the receiver needs to continue.
- Match the checkpoint to the context gap. Ordinary parent–child messages and dependent results use the harness's native channels; a standalone context package is needed only when the receiver lacks that context.
- The receiving side continues that objective and treats completed dependency artifacts as inputs rather than silently reopening or discarding them. An explanation, plan, or review remains that deliverable unless implementation was requested.

**Limits:** [delegation](../delegation.md) owns worker scope, isolation, review, and accounting; evidence that must survive the handoff is [evidence-lifecycle](evidence-lifecycle.md).
