# T3 Code

T3 Code is the host when the tool catalog lists `t3-code` tools, possibly prefixed (`mcp__t3-code__`, `mcp__t3_code__`), or when one direct `orchestrator_capabilities` call succeeds. Catalogs load lazily: a name missing on the first scan is not absence. T3 injects its own orchestration instructions; this note covers only how this collection's methods map onto them.

## Dispatch

- Take the role and model from the [routing table](../routing.md), then the target from `orchestrator_capabilities`: the provider instance that lists that model. Work the native subagent tool can run on that model stays native; other work goes through `delegate_task`.
- A delegated task wakes this thread when it finishes, so end the turn instead of polling. Each review round is a new `delegate_task` call with its own `clientRequestId`.
- The evidence for a delegated step is the child's own thread (`t3_thread_read`), not the parent's summary of it.
- Thread IDs include their prefix (`mcp:<uuid>`). Pass them exactly as a tool returned them; a bare UUID fails with `thread_not_found`.

## Todo

The Claude harness under T3 has no TaskCreate or TodoWrite, and ToolSearch finds none, so don't search for them. Track a multi-step method on the router's `Plan:` line.

## Show

`html_render` publishes a page above the reply; check it with `html_preview` first. show-me, viz, and interactive-explainer say when to use it and how it looks.

Every diagram goes through `html_render`, whichever skill is running: flows, before/after comparisons, call paths, and state through viz, and a Mermaid-only type (class, ER, gantt) through a page that renders it with Pele, as show-me's [html](../../../show-me/references/html.md) shows. A fenced code block holds only code, pseudocode, diffs, and commands; boxes and arrows drawn in one show up as unreadable plain text here.

## Drive

`preview_*` drives a web app in T3's browser, and `device_*` drives an iOS Simulator or Android emulator. When a project has no driver of its own, these are the real surface for verification.

A background process started from a tool call stops at the harness's time limit (about two hours). Run a server that must outlive that in tmux, and give the user its one URL.
