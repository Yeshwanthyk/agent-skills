# Prototype

Use to answer a design or empirical question with disposable work.

State the question and what observation would settle it. Build the smallest artifact that can produce that observation. Reuse project tools where practical and keep experimental output separate from production paths.

Compare alternatives when the choice matters. When it is a novel choice with no established precedent and several viable approaches, read [exhaust-the-design-space](../references/principles/exhaust-the-design-space.md) before picking which to build. When the question turns on a product, UX, or feature-scope tradeoff, read [experience-first](../references/principles/experience-first.md). For visual alternatives, labels and a shared switcher can help the user give a precise verdict. Match the number and form of alternatives to the uncertainty.

Exercise the artifact against the question, not a happy-path demo; read [prove-it-works](../references/principles/prove-it-works.md) before saying the observation settles it, and [explain-the-number](../references/principles/explain-the-number.md) when the observation is a measurement. Report what was learned, and identify the chosen direction or remaining question. A prototype establishes feasibility or preference, not production readiness. Carry it into production only when that work is requested.
