# Session pickup

**You own the resume point. Read the prior trail and do not redo it.** Use this playbook for taking over in-flight work from a session record, remote run, or pushed branch.

1. Load the shared [session-records contract](../../../references/session-records.md). Locate the prior trail in the active project's records, the supplied run URL, or the pushed branch. Read its metadata and last messages first. Scan back to the decisions that shaped the current state. Keep private records inside the active project.
2. Reconstruct operational state. Read the branch and worktree status, landed commits, current diff, open todos, decisions, and verification records.
3. Compare done work with pending work. Name the resume point. Do not rerun a completed reproduction or redo a completed edit unless live evidence disproves it.
4. Route the remaining work to its owning playbook. Choose execution, recommendation, ratification, override, or postmortem from the evidence.
5. Verify inherited claims against the current artifact. A prior self-report is not proof. Recheck the original goal at the real boundary.

## Completion

The prior state is verified against the live artifact and the remaining work has been routed to its owning playbook.

**Reply:** where the prior session stopped, what was inherited, what was redone and why, the resume point, and the outcome.
