Ziggy is my assistant, built on Pi.

Its memory, tools, and scheduled jobs live in a folder I can open and edit.

Why build Ziggy?

I wanted to keep my setup when I changed models or chat apps.

Pi already handles
the agent loop

Ziggy adds memory, scheduled jobs, and agent definitions around Pi. New tools come through extensions.

The gateway calls Ziggy’s agent interfaces rather than running the agent loop itself. ziggy serve brings them together in one process.

Open the folder

The assistant’s folder is called a Profile. Its files hold the instructions, memory, settings, tools, and chat history.

Select a file to see what it does. These are examples, not your files.

Copying the folder should move the assistant’s setup and history. The new machine still needs Ziggy and any tools or integrations it uses.

Use Pi’s extensions

Load an existing package or ask Ziggy to write one. Extension-authoring instructions come with Ziggy.

A cron job starts with a code check

The schedule, prompt, and model settings live in one Markdown file. Each job can choose its provider and model, or use the Profile’s defaults.

Before calling a model, the scheduler runs a gate: a code check for whether there’s work to do.
