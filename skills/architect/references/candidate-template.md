# Candidate architecture template

Use this structure for one independently produced candidate. Replace every bracketed prompt.

## Candidate name

[SHORT NEUTRAL LABEL]

## Usage

Show the caller-facing quickstart and two or three realistic call sites before the type sketch.

## Shape

Describe the data structures, signatures, data flow, module ownership, state authority, dependency direction, validation boundaries, effects, failure channels, observability, migration, rollout, and production and test substitution points.

## Tradeoffs

State what this candidate accepts in exchange for what it gains.

## Alternatives rejected inside this candidate

Name local variations considered while developing this candidate. Do not compare with other Arena candidates, which are not visible during this phase.

## Open questions and risks

Name unresolved evidence and risks that could invalidate this candidate.

## First implementation step

Name the first file or symbol to build if this candidate becomes the selected base.
