## Key conclusions

1. Plannotator identifies the active Codex conversation by inherited `CODEX_THREAD_ID`, not by choosing the newest rollout. It scans `$CODEX_HOME/sessions/YYYY/MM/DD` (default `~/.codex`) newest date first and returns the first `.jsonl` filename containing that thread ID. Discovery errors collapse to `null`. [`apps/hook/server/codex-session.ts:L67-L126`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L67-L126)
2. `plannotator last` deliberately excludes the still-active invocation turn, then takes up to 25 prior assistant `output_text` messages newest-first. This prevents a skill preamble from becoming the target; a picker mitigates `/rewind`, but there is no branch graph. [`apps/hook/server/index.ts:L1126-L1154`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/index.ts#L1126-L1154), [`apps/hook/server/codex-session.ts:L220-L235`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L220-L235), [`apps/hook/server/codex-session.ts:L370-L400`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L370-L400)
3. The Codex parser is intentionally tolerant but weakly bounded: it reads the entire rollout synchronously, silently drops malformed JSON lines, and does not validate file size, snapshot stability, session metadata, or thread identity inside the file. [`apps/hook/server/codex-session.ts:L131-L164`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L131-L164)
4. `review-annotate last` is narrower and fail-closed: it requires the exact `PI_SESSION_FILE`, optionally validates `PI_SESSION_ID`, validates Pi v3 JSONL structure, bounds input to 100 MiB, detects mutation during reading, and follows the active `parentId` chain across the current invocation. It never scans fallback transcripts. [`review-workspace.mjs:L122-L226`](/Users/yesh/.gitgud/skills/review-annotate/scripts/review-workspace.mjs), [`review-workspace.mjs:L371-L394`](/Users/yesh/.gitgud/skills/review-annotate/scripts/review-workspace.mjs)

## Discovery and transcript parsing

Codex origin detection is environment-based: a valid explicit `PLANNOTATOR_ORIGIN` wins, otherwise `CODEX_THREAD_ID` identifies Codex. The annotate-last Codex branch itself still requires the actual thread ID; an origin override alone does not discover a Codex rollout. [`apps/hook/server/index.ts:L309-L329`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/index.ts#L309-L329), [`apps/hook/server/index.ts:L1118-L1155`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/index.ts#L1118-L1155)

The parser accepts only entries shaped as `response_item` → `message` → `assistant`; it retains `output_text` blocks, trims each block, and joins them with newlines. For `last`, the latest unmatched `task_started`/`turn_started` marks the active turn, and scanning ends immediately before it. If those lifecycle markers are missing or the latest turn is already complete, scanning uses the physical end of the rollout. Synthetic tests explicitly cover malformed-line tolerance and preamble exclusion. [`apps/hook/server/codex-session.ts:L147-L164`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L147-L164), [`apps/hook/server/codex-session.ts:L323-L400`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.ts#L323-L400), [`apps/hook/server/codex-session.test.ts:L323-L370`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/codex-session.test.ts#L323-L370)

## Invocation and result delivery

Codex exposes two user paths:

- Shell escape: `!plannotator last`. [`apps/codex/README.md:L104-L112`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/codex/README.md#L104-L112)
- Shared-agent skill: `$plannotator-last`, installed under `~/.agents/skills`. Its prose tells Codex to emit no status message, run `plannotator last` via Bash, wait in the foreground, and incorporate returned feedback. Implicit model invocation is disabled by default in both skill metadata and the OpenAI sidecar; the installer can opt in by changing only installed copies. [`apps/skills/core/plannotator-last/SKILL.md:L1-L31`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/skills/core/plannotator-last/SKILL.md#L1-L31), [`apps/skills/core/plannotator-last/agents/openai.yaml:L1-L5`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/skills/core/plannotator-last/agents/openai.yaml#L1-L5), [`scripts/install.sh:L1165-L1194`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/scripts/install.sh#L1165-L1194), [`scripts/install.sh:L1279-L1299`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/scripts/install.sh#L1279-L1299)

`last` aliases `annotate-last`; `--stdin` bypasses transcript discovery, while `--gate`, `--json`, and `--hook` control approval UX and stdout protocol. Default output is feedback text (approve marker or empty close); JSON emits `approved`/`dismissed`/`annotated`; hook mode emits a blocking reason only for annotations. [`apps/hook/server/cli.ts:L154-L166`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/cli.ts#L154-L166), [`apps/hook/server/annotate-output.ts:L22-L58`](https://github.com/backnotprop/plannotator/blob/a54b46bbee71d7b3f9bf511c9e74db05d21531c2/apps/hook/server/annotate-output.ts#L22-L58)
